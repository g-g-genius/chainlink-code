# skill: bug-fix

## 触发条件
任务描述中包含"修复"、"fix"、"bug"、"报错"、"失败"等关键词

## 流程
1. 理解 bug 描述，提取关键信息：什么操作、什么期望结果、什么实际结果
2. 用 search_code 搜索相关的错误信息、函数名或类名
3. 读取相关的测试文件，理解期望行为
4. 读取相关的源码文件，理解当前实现
5. 定位 bug 的根因——是逻辑错误、边界条件遗漏、类型不匹配还是依赖问题
6. 写出最小化的修复（不要顺手重构不相关的代码）
7. 运行相关测试验证修复
8. 如果测试仍然失败，回到第5步重新分析

## 注意事项
- 修复应该尽量小，一次只改一个地方
- 如果 bug 涉及多个文件的联动问题，先画清调用链再动手
- 如果发现 bug 的根因在外部依赖或基础设施层，不要试图自己修，停下来说明情况
